### S1-T5 投资成本累计逻辑（2 小时）

**规则**（D15）：转入 INVEST 账户 → `costCents += amount`；转出 → `costCents -= amount`（下限 0）。改市值只改 `marketValueCents`，**不生成流水**。

**实现**：`data/repository/RepositoriesImpl.kt`（AccountRepository 实现）加：

```kotlin
suspend fun adjustInvestCost(accountId: String, deltaCents: Long)
suspend fun updateMarketValue(accountId: String, newMarketValueCents: Long)  // 只改市值
```

**调用点接入**（逐个过，grep `insertTxn\|softDeleteTxn\|restoreTxn`）：交易保存（含编辑改金额：先减旧再加工）、删除/恢复流水、周期记账补执行、待报销核销。转账进出 INVEST 账户时调用 `adjustInvestCost`。

**测试**（新 `InvestAccountTest.kt`，≥6 条）：买入 1000 → cost=1000；再买 500 → cost=1500；卖出 600 → cost=900；编辑转账金额 500→700 → cost 修正正确；删除转账 → cost 回退；改市值 → cost 不动、无新流水（断言 txnDao count 不变）。

### S1-T6 净资产口径重算（1.5 小时）

**文件**：`domain/usecase/AssetSummary.kt` 重写（PRD 6.3 口径）：

```kotlin
data class AssetSummary(
    val cash: Long, val savings: Long, val investMarket: Long,   // 资产构成
    val creditDebt: Long, val debtLiability: Long,               // 负债构成
) {
    val assets get() = cash + savings + investMarket
    val liabilities get() = creditDebt + debtLiability
    val net get() = assets - liabilities
}
```

- CASH/SAVINGS：余额为正部分计入资产，负部分（透支）计入负债（保留现有防漏算思想）；
- INVEST：`includeInNetAssets=true` 的按 `marketValueCents` 计入资产；**注意**：投资账户的转账余额与市值并存，口径统一为——投资账户余额即累计转入转出净额，资产侧按市值计，不重复加余额；
- CREDIT：欠款（负余额绝对值）；DEBT：净负债（借入-借出净额，沿用现有 DebtUseCases 口径）。

**测试**（改/新 `AssetSummaryTest.kt`，≥8 条）：五类账户混合、投资计入/不计入、透支储蓄卡、隐藏账户排除、空账户列表。

### S1-T7 资产变化事件存储（1.5 小时）⚠️ 技术决策点

**问题**：「调整市值」「改初始余额」两类事件（D14 要求显示在变化记录里）**没有流水记录**，纯靠流水回算拿不到。PRD 6.4 写「不单独建表」指的是**不做净资产快照表**。

**默认方案（按此执行）**：复用现有 `meta` 表存轻量事件（KV 结构，value 存 JSON：`{ts, kind: MARKET_VALUE|INITIAL_BALANCE, accountId, deltaCents}`），不新建表、不动 schema。变化记录 = 流水回算（收入/支出/退款/坏账/删流水）∪ meta 事件（改市值/改初始余额），按时间倒序合并。`updateMarketValue` 与改初始余额的保存路径各写一条 meta 事件。

**测试**（新 `AssetChangeEventTest.kt`，≥4 条）：改市值写一条事件、改初始余额写一条、事件与流水合并排序正确、转账不产生任何事件。
