# 一心记账

一个**纯本地**的安卓记账 App。记一笔不超过三秒，数据只存在你自己的手机里——不联网、不注册、不上传。

| 项目 | 说明 |
|---|---|
| 包名 | `com.xxjz.ledger` |
| 最低版本 | Android 11（API 30） |
| 目标版本 | Android 15（API 35） |
| 语言 / 界面 | Kotlin 2.2 + Jetpack Compose（Material 3），**零 XML 布局** |
| 当前版本 | 1.9.6（versionCode 17） |

---

## 一、功能一览

**记账**

- 支出 / 收入 / 转账三类流水，计算器键盘（`12.5 + 8 × 2` 直接算），大按钮键盘可选
- 分类两级（大类 + 小类），标签、商家、备注（限 200 字）
- 模板：常用账目一键记；周期记账：按天/周/月/年，支持次数与截止日期
- 待报销（按日期分组可折叠，报销时可选到账账户与日期）、退款（红冲）、借贷台账

**看账**

- 明细按月，按天分组带日小计；日历视图看哪天有账
- 明细 / 报表 / 账户三页可直接左右滑动切换，底栏跟随高亮
- 报表：饼图/柱状/趋势，按大类下钻，年度总结（12 个月双柱 + Top3 分类/商家）
- 预算：总预算与分类预算，超支提醒，日均可用额度
- 账户：五类账户（现金/储蓄卡/信用/借贷/投资）、净资产汇总（资产 - 负债）、投资成本与市值盈亏、隐藏账户不计入
- 信用分期：单笔消费**就地**分期（可填已执行期数，原流水改成本期金额，之后每月自动补一笔）与整期账单分期，期数 2~60，均摊或首期收齐
- 拆分：一笔账拆到多个账户各出各的金额（合计必须等于原额），与记一笔同一套账户口径
- 资产报表：资产与负债构成（可按账户或按类型拆段）、净资产趋势（月/年）、资产变化记录

**数据**

- 加密备份：AES-256-GCM + PBKDF2（12 万轮），导出的 `.bak` 没有密码打不开
- 覆盖导入，导入失败整体回滚；版本不兼容会明确提示而不是写坏数据
- CSV 导出（明细 / 按分类 / 按月）
- 回收站：删除的流水/账户/预算先进回收站，保留天数可设（7/15/30/90/永久）

**系统集成**

- 桌面小组件：本月收支 + 结余，点一下直接记账
- 桌面快捷方式：记一笔 / 报表 / 搜索
- 每日记账提醒（当天已记过就不打扰）
- 应用锁：PIN（4~8 位，PBKDF2 哈希存储）+ 指纹/面容，**每次回到前台都要验**；相机/相册/文件选择豁免一次，10 分钟内有效
- 深色模式、收支配色反转、小数位 0~2 位

## 二、如何构建

### 环境要求

- JDK 17（`JAVA_HOME` 指向它）
- Android SDK，含 Platform 35 与 Build-Tools 35
- 无需联网依赖：仓库里已锁定版本，加 `--offline` 可完全离线构建

### 命令

```bash
export ANDROID_HOME=/path/to/android/sdk
export JAVA_HOME=/path/to/jdk17

# 调试包
./gradlew assembleDebug

# 发布包（会做 R8 混淆 + 资源压缩）
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk

# 单元测试（895 个用例）
./gradlew testDebugUnitTest

# 代码规范
./gradlew ktlintCheck detekt
```

内存吃紧的机器上建议加 `--no-parallel --max-workers=1`，避免 Gradle 守护进程被 OOM 杀掉。

### 签名说明

自用版本使用本机 debug keystore 签名（`app/build.gradle.kts` 里 `signingConfig = signingConfigs.getByName("debug")`）。

- **密钥文件不进仓库**：`.gitignore` 已排除 `*.jks` / `*.keystore` / `local.properties`
- 换机器打包前，先把原 `~/.android/debug.keystore` 拷过去，否则签名不同、无法覆盖安装（需先卸载，卸载会清空数据）
- 如果将来要上架，改成正式 signingConfig 并妥善保管 keystore：**丢了这个文件，老用户就无法升级**

## 三、如何备份与恢复

备份是**唯一**的跨设备迁移手段，也是误删全库后的最后一道防线。

### 备份

1. 我的 → 备份与恢复 → 导出备份
2. 设置密码（至少 6 位，建议记在密码管理器里）
3. 选择保存位置，得到一个 `.bak` 文件

> 密码丢失后**无法恢复**。加密是端到端的，开发者也没有后门。

### 恢复

1. 我的 → 备份与恢复 → 选择备份文件
2. 输入密码 → 看到「将导入 N 笔流水」的预览 → 确认
3. 导入是**整库覆盖**：当前所有数据会被备份内容替换，中途失败会自动回滚

### 建议

- 每月导出一次，文件放网盘或电脑上（App 自己不联网，这一步需要你手动做）
- 回收站默认保留 30 天，误删先看回收站，别急着导入备份

## 四、已知限制

| 限制 | 说明 |
|---|---|
| 不联网 | 没有登录、没有云同步、没有多设备共享。这是设计选择，不是缺失 |
| 提醒可能延迟 | 国产 ROM 的后台限制会让定时任务晚几分钟甚至更久。App 启动时会补执行周期记账，**账目不会漏，只是提醒可能迟到** |
| 备份需手动搬运 | App 不联网，备份文件要自己拷到网盘/电脑 |
| 小组件刷新受系统调度 | 桌面小组件的更新频率由系统决定，通常跟随主界面使用而刷新 |
| 无多币种换算 | 币种字段目前固定 CNY，仅保留结构，不做汇率换算 |
| 不支持的导入格式 | 只认本 App 的加密 `.bak`；CSV 只能导出不能导入（防止字段映射出错导致脏数据） |
| 桌面端 | 无。只有安卓手机端 |

## 五、隐私

- **不申请 INTERNET 权限**：连技术上都无法联网，抓包也抓不到东西
- 只申请四条普通人能理解的权限：通知（提醒）、生物识别（应用锁）、开机自启（恢复定时任务）、相机（拍票据，照片存本地）
- 无埋点、无统计 SDK、无广告
- 备份文件加密后存储，App 私有目录下的数据库不对外暴露

权限清单有自动化测试守着（`ManifestPermissionTest`）：如果以后有依赖偷偷往清单里合并网络/通讯录权限，构建会直接失败。

## 六、代码结构

```
app/src/main/java/com/xxjz/ledger/
├── core/            # 跨功能基础设施
│   ├── common/      # 金额、日期、PIN 哈希、提醒计划、抽象日志
│   ├── designsystem/# 主题、通用组件
│   └── ui/chart/    # 自绘饼图/柱状/折线
├── data/
│   ├── local/       # Room：实体、DAO、迁移、种子数据
│   ├── datastore/   # DataStore：全部偏好设置
│   ├── backup/      # 备份编解码、加密、映射
│   ├── repository/  # 仓库实现
│   └── worker/      # 周期记账、回收站清理、每日提醒
├── domain/          # 模型、仓库接口、用例（纯 Kotlin，无 Android 依赖）
├── feature/         # 按页面分包，每个包 = Screen + ViewModel
├── navigation/      # 路由表与导航图
├── ui/lock/         # 应用锁
└── widget/          # Glance 桌面小组件
```

分层约定：

- `domain` 不依赖 Android，方便纯 JVM 单测
- `feature` 通过仓库接口拿数据，不直接碰 DAO
- 聚合计算放在 DAO 的 SQL 里（有索引），不把全表拉到内存里算

## 七、测试

```bash
./gradlew testDebugUnitTest
```

当前 **895 个用例全绿**，覆盖：

| 类型 | 内容 |
|---|---|
| 纯逻辑单测 | 金额格式化、计算器引擎、日期、周期推算、预算进度、报表聚合 |
| ViewModel 测 | 每个页面的状态流转、边界与错误提示 |

| 备份往返 | 导出 → 导入 → 逐字段比对；损坏文件、密码错误、版本不兼容 |
| 权限审计 | 断言清单里没有网络/通讯录/短信权限；相机权限在而媒体读取权限不在 |

| 性能压测 | 5000 笔账目下聚合 < 300ms、分组 < 200ms（实测 1ms / 11ms） |

性能用例给的是明确上限而不是打印耗时，写坏查询（N+1、全表扫描）会直接红。

## 八、更新日志

### 1.9.6 — 七条试用反馈

- **备份提示改成可关闭**（第 1 条）：首页顶部的备份条右侧加 ×，点掉后静默 7 天，到期若仍未备份会再出现。之前是「要么一直挂、要么直接删」，两头都不合适——提示本身要留，但得让人有办法推开它
- **首页只留最近四笔**（第 2 条）：流水区固定显示最近 4 笔，日期进到流水行第二行（`MM-dd HH:mm`），下方新增「更多明细 · 共 N 笔」卡片进入完整列表。完整列表是独立页面，带月份翻页、搜索、日历入口，并按天分组
  - 顺带修掉一个真 bug：`loading` 期间列表里只有带 key 的预算卡，数据到达后流水插到它前面，`LazyColumn` 以 key 为准保持预算卡视口，整列被顶下去——首屏看上去就停在底部。加载中先不渲染列表
- **拆分原账户自动让出余额**（第 3 条）：只需填新增的那几行，原账户行自动等于「原总额 − 其余各行」，保证合计恒等于原额；一旦手动改了原账户行就停止自动重算（否则填第二行时原账户又被改回去，像是输入被吃掉）
- **金额框点不动**（第 3 条）：新增轻量输入组件 `AmountInput`（`BasicTextField` + 自绘边框，固定 56dp）。旧实现压到 52dp，低于 Material 的 56dp 最小触摸目标，热区被裁；外层又用 `clickable` 包了一层，语义被合并，输入框连语义树都进不去
- **信用账户显示可用额度**（第 4 条）：额度 1000 用掉 500 显示 `-500` + 「可用 ¥500.00」；多还 200 显示 `+200`，只给正号、不标「溢缴」——标了会被当成功能，而这里只是账面余额
- **组合 / 单选来回点不再卡、输入框不再失活**（第 5 条）：组合面板换 `AnimatedVisibility` 渐进展开，分摊行用 `key(account.id)` 固定身份，输入框不再被整体重建
- **账户称呼按类型走**（第 6 条）：支出写「付款账户」、收入写「收款账户」、转账写「转出账户」、借贷写「资金账户」；选账户的校验提示同步改（收入未选时是「请选择收款账户」）
- **三个 Tab 常驻**（第 7 条）：`HorizontalPager` 开 `beyondViewportPageCount`，三页同时组合，切页不再从零组合、不再白屏一帧；跨两页（明细 ↔ 账户）直接定位，不经过中间页
  - 修掉由此暴露的一个状态不同步：`scrollToPage` 只搬位置不刷 `settledPage`，而 `PagerState.scroll` 只在「开滚前没在滚」的空档对齐落定页。滚动刚结束就改目标时，落定页停在旧值，底栏高亮跟着旧值走、返回也退回旧页。补一次零位移滚动让状态对齐

### 1.9.5 — 11 条试用反馈全量处理

- **三页横滑**（第 2 条）：明细 / 报表 / 账户可左右滑动切页，底栏跟随高亮；页内横滚区域（明细页模板条）优先消费手势，滚内容不切页
  - 三个 Tab 从「三个路由」合并成 `main` 一个目的地。若保留三路由用 `navigate` 实现横滑，每次换页都会重建 `NavBackStackEntry`，连带重建 ViewModel——滑过去先闪一帧空页再填数据，比不能滑更难受
  - 切页后按返回回到切页前那一页（不退出应用），历史封顶三层，来回滑十几次也不会变成「按十几次返回才退出」
- **组合支付**（第 1 条）：20dp 的「⇄」小图标改成 48dp 两段式「单账户 / 组合支付」，选中态直接写在按钮上，连点无效的问题从交互层面消失；已填分摊时显示「组合 · N」
- **资金账户口径收紧**（第 3、11 条）：付款只认现金 / 储蓄卡 / 信用，投资账户不可付款但**可转出**（买入与赎回都是转账）；报销到账同样排除投资。付款与转账拆成两套独立口径（`FundPayable`），测试各钉一条
- **首页列表**（第 4 条）：`LazyColumn` 在 `Column` 里用 `fillMaxSize()` 请求的是「父级最大高度」而不是「剩余高度」，列表比可用空间高出一截，可视区只剩四五条、滚到底也够不到预算卡。改用 `weight(1f)` 后拿到剩余高度；顺带加行间分隔线（内缩不通栏）、加大行距
- **流水行信息**（第 5 条）：两行四区——首行「分类 · 备注」+ 金额，次行「时间 · 账户」+ 待报销标记；转账显示 `A → B`
- **月汇总四格**（第 5 条）：收入 / 支出 / 结余 / 待报销（带笔数），点待报销格进待报销页
- **账户页顺序**（第 6 条）：净资产卡上移到页面顶部，待报销从半宽小卡改成整宽横条压在下面
- **首页备份提醒**（第 7 条）：从首页移除（1.9.6 起改成可关闭，见上）
- **拆分**（第 8 条）：独立页面，每行可选账户 + 填金额（与记一笔同一套账户口径），合计必须严格等于原额，2~20 条；旧的「拆成 N 笔等额同账户」整体移除——那种拆法汇总、余额、报表全不变，没有账务意义
- **分期**（第 9、4 条）：就地作用于本笔交易，不再跳账户页。可填期数与本页已执行期数（之前已经还过的期数），原流水改成本期金额，之后每月自动补一笔；启动与每日 Worker 双保险，逐期补齐各落各月
  - schema 升到 9：`installment` 新增 `paidPeriods`（已执行期数）与 `nextRunAt`（下次生成时刻）两列，分别作为进度游标与幂等排期游标；迁移用 `addColumnIfMissing` 保证重放不炸库
- **批量操作返回**（第 10 条）：选中状态下按返回先退出勾选，不再直接回到桌面
- 补 98 条测试（836 总数，0 失败），ktlint / detekt 零违规，versionCode 16

### 1.9.4 — 五处体验修正

- **报表饼图引线**：起点从色块外缘挪到环中线，线头埋进色块；沿扇区中角直出 4dp 再折向水平；肘部外扩 12dp → 4dp；去掉起点圆点；标签列 88 → 96dp，账户名可用宽度约 70 → 86dp
- **待报销确认**新增三项：到账账户（默认原支出账户，只列现金/储蓄卡/投资三类资金账户并显示余额）、报销日期、报销时间。入账金额仍默认支出全额、仍校验 1..支出金额
  - 报销收入写进所选账户与所选时间，原支出的金额/日期/账户/分类一个都不动；撤销逻辑不变
  - 报销日期与操作时刻是两个参数：前者决定明细分组与报表归属月，后者只记 `createdAt` / `reimbursedAt`
  - 原账户被删或被隐藏时不预选、提示「原账户已不可用」并置灰确认——涉及钱的默认值不猜
- **组合支付「⇄」连点无效**：根因是 UI 把算好的 `!state.splitMode` 往下传，连点第二次仍绑在同一快照上。改由 ViewModel 的 `toggleSplitMode()` 基于最新状态翻转，连点必定一开一关
- **流水删除入口**：移除左滑删除（含红底与 `SwipeToDismissBox`）；长按抽屉最底层新增红色「删除」，点击软删除、关抽屉、提示「已移入回收站」，不弹二次确认。批量删除操作栏不动
- **待报销按日期分组**：按 `dateKey` 倒序分组、组内时间倒序，组头「今天 · 2 笔」+ 合计 + 折叠箭头，整行可点；默认全部折叠，展开状态会话级；顶部「N 笔」汇总不变；已报销仍平铺
- 补 28 条测试（738 总数，0 失败），ktlint / detekt 零违规，versionCode 15

### 1.9.3 — 记账页与资产报表按视觉稿重做，锁屏口径收紧

- **应用锁**：取消 60 秒宽限期，只要离开过就上锁。相机/相册/文件选择走一次性豁免名额（`beginTrustedLeave`），在回前台时消耗；名额 10 分钟未用自动失效，防止外部 Activity 被系统杀掉后锁永久失效。无 PIN 时不上锁，避免把用户关在门外
- **相机闪退**（三个独立根因）：权限声明了却从未运行时申请 → `SecurityException`；压缩在主线程做 → 低端机 ANR；采样率用 `&&` 判长短边 → 4000×3000 不采样，按 48MB 原图解码 OOM。分别改为权限三态引导（直接开 / 降级相册 / 引导设置）、`Dispatchers.IO` + 转圈禁点、只看长边
- **记账记忆**：记住上次用的分类与付款账户，优先级「本次会话选过的 → 持久记忆 → 默认账户 / 最高频分类 → 唯一账户」。编辑旧账与套模板不写入，避免污染习惯
- **资产报表**：去掉 `TopAppBar` 改用紧凑标题栏；卡片改浅灰底圆角 20、无描边无彩点；去掉页头大字净资产，金额并进饼图上方总额行；圆心不再常显数字；资产块与负债块**各带一套**「按账户 / 按类型」开关，两套口径总额恒等
